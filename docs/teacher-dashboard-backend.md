# Teacher Dashboard backend (Stage 6)

Stage 6 adds authenticated PostgreSQL RPCs for class analytics. Call each function with the signed-in teacher's Supabase session. Every public function is `SECURITY DEFINER` with an empty `search_path`, but it checks the authenticated teacher role and class ownership server-side before reading analytics data. The class ID is never trusted merely because it came from a client. Class-specific assessment IDs are checked against that class, and student drill-down requires that the student has an enrollment record in the authorized class. Direct table access remains subject to the existing RLS policies.

Unauthenticated requests return SQLSTATE `28000`; a non-teacher, foreign class, mismatched assessment, or student outside the class returns `42501`; a nonexistent topic filter returns `22023`. An empty authorized result is valid and is not an authorization signal. Responses use `schema_version: 1` where the endpoint returns an object.

## API contracts

| RPC | Arguments | Result |
|---|---|---|
| `public.list_teacher_classes()` | none | JSON array of the caller's classes with class metadata, active enrollment count, and assessment count. No other teacher's classes are queried. |
| `public.get_teacher_class_overview(p_class_id uuid)` | owned class | `{schema_version, class, class_performance, assessment_summaries[], topic_mastery_distribution[]}`. The class object includes the active roster count; assessment cards include participation/performance metrics. |
| `public.get_teacher_assessment_analytics(p_class_id uuid, p_assessment_id uuid)` | owned class and its assessment | `{schema_version, class_id, assessment_id, analytics, topic_performance[]}`. A mismatched assessment is denied, not treated as an empty result. |
| `public.get_teacher_misconception_heatmap(p_class_id uuid, p_assessment_id uuid default null, p_topic_id uuid default null)` | owned class; optional assessment/topic filters | `{schema_version, class_id, assessment_id, topic_id, active_enrollment_count, cells[], candidate_interpretation, empty_scope_note}`. Each cell has topic/code, candidate attempts and students, eligible graded-attempt denominator, rates, and an explicit `possible_pattern_not_confirmed` interpretation. |
| `public.get_teacher_students_needing_support(p_class_id uuid)` | owned class | `{schema_version, active_enrollment_count, students_for_review[], insufficient_evidence[], criteria}`. Entries use student ID/display name because this is an authorized teacher-only workflow; reasons and evidence are included. |
| `public.get_teacher_student_learning_detail(p_class_id uuid, p_student_id uuid)` | owned class and enrolled student | Student profile display name/enrollment status, up to 50 most recent attempt summaries, latest graded topic observations, and uncertainty-labeled candidate signals. It does not return submitted answer JSON or answer keys. |
| `public.get_teacher_teaching_recommendations(p_class_id uuid)` | owned class | `{schema_version, class_id, recommendations[], empty_evidence_note}`. Every recommendation includes its topic, persisted evidence, threshold/basis, and a supportive caveat. |
| `public.get_teacher_assessment_report_data(p_class_id uuid, p_assessment_id uuid)` | owned class and its assessment | Class/assessment metadata, aggregate metrics, topic and question summaries, and export-safety metadata. It contains no student identifiers, submitted answer text, or answer keys. |

The TypeScript `Database` function map includes all RPC names and argument shapes. The report RPC provides safe aggregate data for a future export screen; the backend does not create or store a CSV/PDF file in this stage. Any future export must call this authorization-checked RPC with the teacher's session rather than export client-side data fetched from unrelated tables.

## Metric definitions

- **Active enrollment denominator:** count of `enrollments.status = 'active'` in the class at query time. Withdrawn enrollments are not part of current class aggregates.
- **Assessment participation:** unique active-roster learners with any persisted attempt for the assessment, including an in-progress, submitted-but-ungraded, or abandoned attempt. Participation rate is participating learners divided by active enrollments; it is `null` for an empty active roster.
- **Unfinished attempts:** attempt records in `in_progress`, `submitted`, or `abandoned` status. Counts are attempt-level, not learner-level. These records are not included in score averages.
- **Assessment score average and median:** one latest **graded** attempt per active enrolled learner, ordered by attempt number and submitted time. If a learner later starts an unfinished retake, the previous graded score remains eligible. The denominator is the number of active enrolled learners with at least one graded attempt; it is not the full roster.
- **Class performance:** one latest graded attempt for each active learner/assessment pair. The observation count is the number of such learner-assessment pairs; a learner may contribute once for each assessment.
- **Topic mastery:** for each learner/topic, aggregate all scored items from that learner's latest graded attempt per assessment. The topic score is earned points divided by possible points, expressed as a percentage. Persisted unanswered items in a graded attempt earn zero and remain in the possible-points denominator. Distribution bands are `<40` (`below_40_further_practice`), `40 to <70` (`40_to_below_70_developing`), and `>=70` (`70_or_above_secure_for_now`). Band percentages use only learners with scored evidence for that topic; active learners without topic evidence are separately counted. A topic assigned to an assessment but with no graded evidence is returned with zero evidence and null rates.
- **Heatmap rate:** candidate attempts for a topic/code divided by eligible latest graded attempts that included at least one question from that topic. Each attempt/topic/code is counted at most once even if duplicate candidate rows exist. Student rate uses active enrollment count. These are counts/rates of diagnosis records, **not confirmed misconception prevalence**. A blank heatmap can mean no supported diagnosis record was available, not that no learner struggled.
- **Students for review:** an active learner is included when either (a) at least two distinct graded assessments are available and the mean of up to the three latest graded assessment observations is `<=60%`, (b) an answered incorrect response recurs in the same topic across at least two latest graded assessments, or (c) the same diagnosis code occurs in at least two latest graded assessments. Incomplete attempts are excluded from score criteria. Criterion (c) remains an uncertain candidate signal. The response provides the specific criterion/evidence and frames it as an invitation to check in, not a learner label.
- **Insufficient evidence:** active learners with fewer than two distinct graded assessments and no review criterion are placed in a separate evidence-gap list. This is not a performance concern. Learners who meet neither category are omitted from this endpoint's two lists.
- **Recommendations:** a class-level topic mean below 70% across at least two learners yields a review/practice prompt; mean below 40% suggests a small-group revision session. Repeated diagnosis codes can produce a targeted-practice prompt only as candidate evidence. No model-generated or ungrounded data is used.
- **Question report accuracy:** mean persisted item score from the latest graded attempt per active enrolled learner. Correct responses score 100, wrong and unanswered graded responses score 0. Reports contain counts and aggregates only, not answer content or keys.

## Uncertainty and supportive language

The heatmap, student detail, support criteria, and recommendations describe diagnosis rows as possible/candidate patterns and use the literal interpretation `possible_pattern_not_confirmed`. A confidence value is not converted to a probability, and no response pattern is stated to establish a student's reasoning or personal traits. Persisted incorrect answers are reported as observed assessment evidence. Evidence gaps are called insufficient evidence, not failure.

## Security and test coverage

All RPC entry points are revoked from `PUBLIC`, `anon`, and `service_role`, then granted to `authenticated`. Internal analytics helpers are not executable by API roles. Every class/assessment query is constrained by the authorized class ID; student-level queries additionally require class enrollment. The report deliberately omits names and student IDs. `supabase/tests/teacher_dashboard.test.sql` covers aggregate arithmetic, empty classes, in-progress/incomplete attempts, role denial, cross-class denial, student-detail scope, and uncertain candidate wording. `tests/test_teacher_dashboard_contract.py` checks the migration/API contract statically. PostgreSQL execution requires the local Supabase CLI, Docker, and pgTAP; static Python checks do not substitute for database execution.
